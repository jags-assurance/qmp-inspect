Every screen, who it's for, and what it proves.

This is the walkthrough behind the live prototype — one page per persona, in the order a project actually moves through them, from the first ITP draft to the handover certificate. Use it to navigate the demo with Naresh, or to check a screen against the reference mockups without re-opening the whole deck.

2 tenants modelled — Meridian Energy (full data), Northgate Rail (mobilisation-stage)
7 personas, one login
19 reference screens covered

The chain of custody, in six moves

Every inspection in QMP Inspect follows this path — the same six roles hand the record forward, no matter the discipline.
1
Admin draftsITP built from the spec, parties assigned
2
All parties signContractor, Sub, TPI, Client approve
3
Sub executesField checklist, photos, signature
4
TPI / Contractor verifyIndependent measurement + review
5
Inspector decidesPass → IRN, or Fail → NCR
6
Client receivesData Book, KPIs, Handover Portal
01

Jags Admin

Priya Desai

The build-and-govern seat. Everything downstream — every checklist a Subcontractor fills, every H/W/R/S pill a Contractor sees — starts here: pulling a spec out of the Vault, drafting an ITP against it, and deciding which parties are even active on a given project.

Orbit Homeadmin · dash

Landing screen after login — the portfolio view across every tenant, not just one project.

Shows

  • 4 KPI tiles: active clients, active projects, parties, open NCRs
  • Licensed-module grid (QMP Inspect active, others greyed "Not enabled")
  • My Work + Recent Projects cards

Proves

  • This is one platform serving many clients, not a single-project tool

Start Workadmin · startWork

The fork in the road before anything gets created — pick the workflow that matches the engagement.

Shows

  • ITP-driven project card — full workflow, multi-party sign-off
  • Standalone assignment card — quick setup for a one-off FAT or vendor visit

Proves

  • Not every job needs a full ITP — Jags doesn't force process onto a 2-hour vendor test

Project Setupadmin · setup

Where a project's parties are assigned and switched on or off.

Shows

  • Party table: Contractor, Subcontractor, TPI/Lab, Jags, Client
  • Active / not-required toggle per party

Proves

  • Deactivating a party (say, no TPI on this job) correctly drops them from every sign-off list downstream — packages, assignments, approvals — without leaving a stuck "pending forever" slot

Central Vaultadmin · vault

The revision-controlled source of every drawing and spec — and the on-ramp into AI-assisted ITP drafting.

Shows

  • 4 stat tiles (documents / controlled / awaiting review / last synced)
  • 11 folders (Drawings, Specifications, Standards…)
  • Selected-document detail: metadata, linked standards, revision
  • "Ready for ITP generation" card → Generate ITP from this specification

Proves

  • The ITP isn't typed from scratch — it's drafted from the client's own approved spec, with the source document traceable

ITP Builderadmin · itp

Where the AI-suggested draft becomes a controlled, section-by-section document.

Shows

  • Dismissible "AI-drafted — review required" banner
  • Full activity table across Submittals / Execution / Testing / Handover, with H/W/R/S party pills
  • Per-row status: Confirmed vs. Review, inline edit panel
  • Footer: "9 activities · 6 confirmed · 3 need review"

Proves

  • AI never writes directly to the approved ITP — a Jags engineer confirms every suggested row before it counts

Checklists & Formsadmin · checklists

The field checklist a Subcontractor will answer, built once and linked to its ITP activity.

Shows

  • Drag-ordered item list, one expandable for options (measured value + unit, photo-required-on-No, helper text)
  • Live tablet preview, Desktop/Tablet toggle

Proves

  • What Admin builds here is exactly what the Subcontractor sees on-site — same items, same order, same rules

ITP Packages & FAT / Assignmentsadmin · packages · assignments

Trade-scoped ITPs (Flooring, Ceilings, Painting, Electrical) and standalone tests that don't need a full project ITP.

Shows

  • Assignment-type tabs: FAT / Witness inspection / Specific test / Pre-shipment
  • Manufacturer/Model/Serial-Tag + Attached-checklist card
  • Tabbed detail: Measurements, Photos, Punch List, Witness Signatures, Notes
  • Generated FAT Report (A4): doc control, checklist results, evidence photos, Conditional-Pass banner if punch items remain open

Proves

  • A factory acceptance test for one pump skid gets the same rigor as a building-wide ITP — just scoped down

Registersadmin · registers

Live registers for everything the project has generated — not static exports.

Shows

  • Punch-List, NCR and Observation registers with stat tiles + aging-profile chart (0–7 / 8–14 / 15–30 / 30+ days)
  • Project / Type / Status filters + search, Due-date and Days-open columns
  • Calibration, Welder and Material registers

Proves

  • Nothing on Northgate Rail (still in mobilisation) shows fabricated Meridian data — registers correctly render empty with an explanatory banner per tenant

ITP Registeradmin · register

Every ITP across every client, one table.

Shows

  • Stat tiles, working search + Project/Discipline/Status filters
  • % complete progress bar, Open-items, Updated columns, Actions menu

Proves

  • A Jags Admin managing 12 projects doesn't need to open each one to know what's stuck

Data Book Builderadmin · databookBuilder

The QM's own verification workspace — distinct from the client-facing Data Book progress view.

Shows

  • 5 dossier sections (ITPs, Inspection records, Test certs, NCRs closed, As-builts), each "X of Y verified"
  • Readiness donut, recent verification events
  • Locked "Compile Data Book" until every section clears

Proves

  • Handover isn't a button — it's gated on someone actually verifying every record first

Power BI (Internal)admin · powerbi

Jags' own cross-portfolio analytics — never shown to a client.

Shows

  • Date/Region/Client/Project filter bar
  • 5 charts: completed-vs-planned, pass-rate trend, NCR trend, hold-point-turnaround gauge, data-book readiness by project
  • Vendor performance league table with trend sparklines

Proves

  • Jags manages quality across its whole book of business, not project-by-project in spreadsheets

Approvals Centre & Users/Settingsadmin · approval · settings

Every outstanding sign-off across every client, and the full user/role roster.

Shows

  • One list of every pending signature — ITP-001, packages, FAT assignments — filtered to what's yours
  • Dynamic Users table built from every tenant's actual party roster

Proves

  • A Contractor with minimal nav can still sign off a package from one central place
Handoff → once every party has signed ITP-001, the record moves from "being built" to "being executed" — the next three roles never see an unsigned ITP.
02

Jags Inspector

Ravi Kapoor

The independent decision-maker. Everyone else's evidence — the Subcontractor's checklist, the TPI's measurement — lands here, and the Inspector makes the one call that actually matters: pass, or raise a non-conformance.

Inspector Dashboardinspector · dash

A working day, not a to-do list.

Shows

  • 4 KPI tiles with context ("3 due today", "Oldest: 3 days")
  • All / Today / Overdue pending-actions table
  • Awaiting-my-sign-off panel, Today's schedule strip

Proves

  • An inspector juggling 12 active projects can see what's actually urgent without opening each one

Inspect Activityinspector · inspect

The core inspection screen — every piece of evidence, gated in order.

Shows

  • Subcontractor checklist / Contractor review / TPI measurement / Client witness status, each blocking the next
  • Pass & Issue IRN, or Fail & Raise NCR

Proves

  • An Inspector physically cannot record Pass while a field item is still flagged — the button disables itself

New NCR / Observationinspector · inspect (on Fail)

Raising a non-conformance is a controlled form, not a text box.

Shows

  • Traceability block, AI-drafted description badge (review required)
  • Minor vs. Major severity choice, requirement-not-met citation, photo attach, Inspector signature

Proves

  • A Major NCR routes to the Client for acknowledgement (ISO 17020 impartiality) — a Minor one closes at Jags alone

Inspection Recordinspector · irn

The full IRN detail, and the letterhead document it generates.

Shows

  • Tally tiles (items / Yes / No / N-A) + big PASS result
  • Results table with photo-evidence thumbnails, 3-step approval timeline, audit trail
  • Right panel: the generated Inspection Release Note with 4-party signatures

Proves

  • The printable release note isn't a separate re-entry — it's generated straight from the same recorded evidence

NCR Registerinspector · ncr

Every non-conformance this Inspector has raised, tracked to closure.

Handoff → a Pass releases the activity forward; a Fail sends a corrective-action request to the Contractor — that's where the next persona picks it up.

Independent, third-party — this persona never sees or edits anyone else's evidence, only submits its own measurement against a stated tolerance.

07

Documents & Reports

Reachable from Reports & Certificates

Every formatted output the platform generates — each one built from live state, not a static mock. Switching Meridian → Northgate in the demo re-renders every one of these from Northgate's own (mostly pre-execution) data.

Inspection Release Notice (IRN)

Letterhead doc, 4-party signature block, generated the moment an Inspector records Pass.

Inspection Report (A4)

The generic inspection report — traceability, summary stats, results table, evidence photos, conclusion, observation callout, 3-way sign-off. Distinct from the IRN: this is the discipline-level report, not the release note.

Final ITP — 3-page controlled document

Party Codes legend (C/SC/TPI/JA/CL), Point Types legend (H/W/R/S), per-row sign-off column, Distribution List, revision history, repeated Approvals block.

NCR Close-Out Certificate

Root cause / Corrective action / Preventive action / Verification of effectiveness, each as its own section, plus a closure-confirmation banner.

FAT Report (A4)

Document control box, checklist results, measurements, embedded photos, punch list with category/owner/target close-out, and a Conditional-Pass banner that only appears when punch items are genuinely still open.

Weekly / Monthly Quality Report

Cover page, executive summary, KPI tiles, progress-per-project bars, NCR open/closed donut, vendor performance ranking.

Handover Certificate

Issued once the Data Book gates clear — or conditionally, with the documented exception carried on the certificate itself.
